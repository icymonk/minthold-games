# 개발 단계 계획

기획: `docs/design.md`

각 항목은 PR 하나 단위다. 위에서부터 차례로 진행한다. 이 게임은 그래픽이 핵심이라 3D 숲 검증(0-2, 0-3)을 규칙 엔진보다 먼저 한다.

## 0단계 — 기반·그래픽 검증
- [x] 0-1 Godot 4.7 3D 프로젝트, 화면 전환 뼈대, gdUnit4, CI(`grove.yml` → 공용 `godot.yml`), 웹 미리보기 `minthold-grove`
- [x] 0-2 3D 숲 섬: CC0 팩 받기(`tools/art_bake/fetch.sh`), 재질 셰이더 통일, 나무 8종·`Socket` 4개, 카메라(비스듬한 고정·90° 회전), 바람 셰이더, 계절 색 4종, 웹 프레임 측정, 1080p 스크린샷
- [x] 0-3 카드 → 숲 붙이기 연출 프로토타입(규칙 없이): 손패 끌기, 자리 빛, 반투명 미리 보기, 종류별 등장 6종, 카드 초상 굽기, `Coach` 뼈대

## 1단계 — 규칙 엔진 (화면 없이 테스트로 검증)
- [x] 1-1 카드 데이터(나무 8, 이웃 24), `Forest`(4방향 자리·묘목·굴), `Season.play`(비용·반쪽·효과→보너스), 빈터 쓸림, 테스트
- [ ] 1-2 `Score`(세트·종류 수·같은 나무·꽉 찬 나무 등 패턴), 버섯 지속 효과(`Hook`), 계절 바람 3장, `SeasonLog`·`ScoreLog`, 테스트
- [ ] 1-3 `Run`(4계절): 숲 유지, 계절 목표·사건, 오두막 보상·도토리, seed 결정론, 헤드리스 봇 `tools/sim.gd`

## 2단계 — 한 계절 (재미 검증 1: "카드를 낼 때 숲이 자라는 게 재밌나")
- [ ] 2-1 계절 화면: 3D 숲 + 손패·빈터·바람 칸을 규칙에 연결, 예상 점수, 계절 끝 점수 연출(6.6), 실패 연출
- [ ] 2-2 오두막 화면(보상 3장 중 1장, 상점, 땅 넓히기), 런 끝 화면(숲 360°), 안내 1~5단계

## 3단계 — 한 런 (재미 검증 2: "빌드가 생기나")
- [ ] 3-1 이웃 40종, 숲 정령 30종, 카드 꾸미기, 종류별 3D 모델·대기 애니메이션 채우기
- [ ] 3-2 계절 사건 16종, 이웃끼리 반응 연출, 계절 소품(꽃잎·반딧불·낙엽·눈), 숲 소리 겹치기
- [ ] 3-3 저장(계절 사이 이어 하기), 기록, 숲 도감(해금)

## 4단계 — 오래 하기 (재미 검증 3: "5시간 뒤에도 한 해 더 하고 싶나")
- [ ] 4-1 숲지기 8명, 숲 등급 8단계, 내 숲 앨범
- [ ] 4-2 이웃 90종·정령 60종·사건 32종으로 확장, 끝없는 해, 오늘의 숲(일일 seed)
- [ ] 4-3 밸런스: 봇 2000판으로 계절 목표·카드 점수 조정, 첫 완주까지 시간 측정, 웹 성능 다듬기
