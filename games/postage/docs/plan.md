# 개발 단계 계획

기획: `docs/design.md`

각 항목은 PR 하나 단위다. 위에서부터 차례로 진행한다.

## 0단계 — 기반
- [ ] 0-1 Godot 4.7 프로젝트, 화면 전환 뼈대, gdUnit4, CI(`postage.yml` → 공용 `godot.yml`), 웹 미리보기 `minthold-postage`

## 1단계 — 규칙 엔진 (화면 없이 테스트로 검증)
- [ ] 1-1 카드 데이터(우표·소포·혜택, JSON 또는 Resource), 더미·진열대·버림 더미, 시드 고정 섞기
- [ ] 1-2 요금 조건 판정기: 우표첩 + 동전 + 선납 우표 + 혜택으로 조건을 맞추는 조합 찾기, 테스트
- [ ] 1-3 턴 진행: 행동 4종, 행동 3번, 우표첩 한도, 반송 소포, 대기 줄 보너스, 마감 시계, 종료·승패

## 2단계 — 한 판 화면 (재미 검증 1: "조합 맞추기가 재밌나")
- [ ] 2-1 책상 화면: 진열대, 대기 소포, 내 창구 2칸, 우표첩, 행동 남은 수
- [ ] 2-2 우표 끌어다 붙이기, 보낼 수 있는 소포 표시, 동전 쓰기, 발송 연출(소인)
- [ ] 2-3 AI 1명(신입 민지)과 한 판, 결과 화면

## 3단계 — 혜택과 AI (재미 검증 2: "창구가 굴러가나")
- [ ] 3-1 1회 혜택 5종, 영구 혜택 9종
- [ ] 3-2 AI 3명(성향별 점수 매기기), AI 턴 배속·건너뛰기
- [ ] 3-3 밸런스 봇: AI끼리 시드 200판, 혜택별 승률·평균 판 길이 출력

## 4단계 — 다듬기
- [ ] 4-1 첫 판 안내(행동 3번, 조건 읽는 법), 늘 보이는 도움말
- [ ] 4-2 저장(판 중간 이어 하기), 설정, 번역(ko/en), 효과음

## 5단계 — 확장·출시 (MVP 이후)
- 근무 주간, 오늘의 우체국, 카드 해금, 핫시트, 일러스트 교체, Steam 상점 페이지
