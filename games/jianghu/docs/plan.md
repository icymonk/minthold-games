# 개발 단계 계획

기획: `docs/design.md`

각 항목은 PR 하나 단위다. 위에서부터 차례로 진행한다.

## 0단계 — 기반
- [ ] 0-1 Godot 4.7 프로젝트, 화면 전환 뼈대, gdUnit4, CI(`jianghu.yml` → 공용 `godot.yml`), 웹 미리보기 `minthold-jianghu`
- [ ] 0-2 도형·수묵 그림(협객·적·카드·결 아이콘), 코드 효과음, `Coach` 단계별 안내 뼈대

## 1단계 — 규칙 엔진 (화면 없이 테스트로 검증)
- [ ] 1-1 카드 데이터, 덱·뽑기·버리기·소멸, 내공, 피해·호신강기, 테스트
- [ ] 1-2 `Chain`: 결 연계, 비급 순서, 연계 배수, 비기 발동, `BattleLog`, 테스트
- [ ] 1-3 `Battle`(적 의도 AI), `Run`(3막 `ActMap`, 보상), seed 결정론, 헤드리스 봇 `tools/sim.gd`

## 2단계 — 한 싸움 (재미 검증 1: "순서 맞추기가 재밌나")
- [ ] 2-1 전투 화면: 손패·내공·적 의도·비급 막대, 카드 끌어 내기, 비기 연출, 실패 연출
- [ ] 2-2 갈림길 지도, 보상 화면, 객잔 화면(묵기·운기조식·가게), 런 끝 일지, 안내 1~5단계

## 3단계 — 한 런 (재미 검증 2: "비급 조합으로 빌드가 갈리나")
- [ ] 3-1 화산파 카드 70장, 비급 30권, 소모품 10종
- [ ] 3-2 일반 적 15, 강적 6, 장문인 3, 기연 20
- [ ] 3-3 저장(칸 사이 이어 하기), 기록, 무림 비록(해금)

## 4단계 — 오래 하기 (재미 검증 3: "5시간 뒤에도 한 판 더 하고 싶나")
- [ ] 4-1 문파 6개, 마두 단계 15, 협객 고용, 정파·사파 명성
- [ ] 4-2 카드 180·비급 70·장문인 9로 확장, 끝없는 강호, 오늘의 강호(일일 seed)
- [ ] 4-3 밸런스: 봇 2000판으로 적 체력·피해·비급 조정, 첫 완주까지 시간 측정

## 5단계 — 다듬기·출시
- [ ] 5-1 번역(ko/en), 효과음·연출 다듬기, 패드 조작
- Steam 상점 페이지 검토
