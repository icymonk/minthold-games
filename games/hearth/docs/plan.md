# 개발 단계 계획

기획: `docs/design.md`

각 항목은 PR 하나 단위다. 위에서부터 차례로 진행한다.

## 0단계 — 기반
- [ ] 0-1 Godot 4.7 프로젝트, 화면 전환 뼈대, gdUnit4, CI(`hearth.yml` → 공용 `godot.yml`), 웹 미리보기 `minthold-hearth`
- [ ] 0-2 도형 그림(난로·줄·카드·생존자), 불꽃 밝기 연출, 코드 효과음, `Coach` 단계별 안내 뼈대

## 1단계 — 규칙 엔진 (화면 없이 테스트로 검증)
- [ ] 1-1 카드 데이터, 덱·뽑기·버리기, `Hearth`(불꽃·장작), 피해 = 열 × 불꽃 × 연쇄, 테스트
- [ ] 1-2 `Night`: 줄 3개, 위협 이동·도달 효과, 6턴 새벽, `NightLog`, 테스트
- [ ] 1-3 `Run`(12밤): `ForestMap`, `Expedition`, 저녁(식량·카드 정리), 보상, seed 결정론, 헤드리스 봇 `tools/sim.gd`

## 2단계 — 한 밤 (재미 검증 1: "불을 태울지 아낄지 고민되나")
- [ ] 2-1 밤 화면: 난로·줄·손패, 카드 끌어 놓기, 피해 연출, 실패 연출
- [ ] 2-2 낮 숲 지도, 저녁 산장 화면, 런 끝 일지 화면, 안내 1~5단계

## 3단계 — 한 런 (재미 검증 2: "생존자 조합마다 빌드가 갈리나")
- [ ] 3-1 생존자 5명, 카드 60장, 산장 물건 30종
- [ ] 3-2 위협 12종, 보스 6종, 숲 이벤트 20종, 사기 이벤트
- [ ] 3-3 저장(밤 사이 이어 하기), 기록, 산장 일지(해금)

## 4단계 — 오래 하기 (재미 검증 3: "5시간 뒤에도 한 겨울 더 하고 싶나")
- [ ] 4-1 생존자 8명, 시작 조합 고르기, 혹한 단계 10, 수상한 사람(도둑)
- [ ] 4-2 카드 120·물건 60·보스 12로 확장, 끝없는 겨울, 오늘의 눈보라(일일 seed)
- [ ] 4-3 밸런스: 봇 2000판으로 밤별 위협·장작 수급 조정, 첫 구조까지 시간 측정

## 5단계 — 다듬기·출시
- [ ] 5-1 번역(ko/en), 효과음·연출 다듬기, 패드 조작
- Steam 상점 페이지 검토
