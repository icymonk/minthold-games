# 개발 단계 계획

기획: `docs/design.md` · 구조: `docs/architecture.md`

각 항목은 PR 하나 단위다. 위에서부터 차례로 진행한다.

## 0단계 — 기반
- [x] 0-1 Godot 4.7 프로젝트, 화면 전환 뼈대, gdUnit4, CI(`desk.yml` → 공용 `godot.yml`), 웹 미리보기 `minthold-desk`

## 1단계 — 규칙 (화면 없이 테스트로 검증)
- [x] 1-1 `Match` 엔진: 카드 0~42와 뛰기 값, 구역 더미 3개, 준비·처음 손패, 뽑기, 기록 내기(뛰기)·쉬기, 하나·여러 개 짚기, 승리 판정, 마지막 추궁, 테스트
- [x] 1-2 `Knowledge`(쪽마다 아는 것) + `Deduce`(뒷면 기록별 번호 분포), 테스트
- [x] 1-3 `Bot` 1차(AI 팀장·AI 사원, 성격 3종), 헤드리스 시뮬레이터 `tools/sim.gd`

## 2단계 — 한 판 (재미 검증 1: "팀장으로 범위를 좁히는 게 재밌나")
- [x] 2-1 테이블 화면: 벽시계, 구역 더미, 가운데 줄(뒷면·뛰기 장수), 손패, 기록 줄, 역할 선택
- [x] 2-2 팀장 조작: 메모판(자동 지우기·직접 표시), 하나·여러 개 짚기, 뒤집기 연출
- [x] 2-3 사원 조작: 끌어서 기록 내기, 뛰기 칸, 낼 수 있는 번호 표시, 쉬기
- [x] 2-4 마지막 추궁 연출, 결과 화면, 다시 하기, 규칙 요약(늘 열기), 첫 판 안내

## 3단계 — 다듬기 (재미 검증 2: "한 판 더 하고 싶나")
- [ ] 3-1 장소·인물 그림, 효과음, 움직임
- [ ] 3-2 밸런스: 시뮬레이터로 뛰기 값·처음 손패·AI 성격 조정, 난이도 3단계
- [ ] 3-3 사건 카드 10종(설정에서 켜기)
- [ ] 3-4 한 주(월~금 5판), 기록·저장, 시드 입력
- [ ] 3-5 번역(ko/en) 검수
